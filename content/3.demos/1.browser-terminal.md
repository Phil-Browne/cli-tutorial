# Browser Terminal

The full Megaport CLI runs in your browser via WebAssembly. The same binary you'd install locally — compiled to WASM and loaded directly in this tab. No install, no PATH, no setup.

---

## Get your credentials

You'll need a Megaport API key. Use **Staging** for demos — it's a full API environment with no billing impact.

1. Go to [portal.megaport.com](https://portal.megaport.com)
2. Click your account name → **My Account**
3. Select **API & Credentials**
4. Create a new API key pair and copy the **Access Key** and **Secret Key**

::info-card{type="tip" title="Use Staging for demos"}
Staging (`api.megaport.com/v2` with staging credentials) is a safe environment for exploration and customer demos. Resources provisioned in staging do not incur charges.
::

## Getting started

Once connected, try these commands:

```bash
# Browse the global network — 700+ data centres
megaport-cli locations list

# Filter to a metro area
megaport-cli locations list --metro Sydney

# List your ports
megaport-cli ports list

# JSON output — ready for jq or scripting
megaport-cli locations list --output json
```

::info-card{type="note" title="Browser limitations"}
A few commands are not available in the browser WASM environment:

- **`--interactive` / `-i` mode** — requires a TTY that isn't available in the browser
- **`config` commands** — no file system access, so config profiles cannot be read or written
- **Authentication** — use the form above instead of `megaport-cli configure`

All read operations (`list`, `get`, `status`) and write operations (`buy`, `update`, `delete`) work normally.
::

::info-card{type="warning" title="Security"}
Your credentials are stored **in this browser tab's memory only**.

- Never written to disk or localStorage
- Never sent anywhere except the Megaport API
- Cleared when you close or refresh this tab

If you're sharing your screen during a demo, use a dedicated staging API key that you can rotate after the session.
::
